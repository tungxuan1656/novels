# Review Checklist

Use this checklist for an audit, a rewrite, or a multi-document delivery.

## Responsibility

- [ ] The document owns one class of truth.
- [ ] The title and first section reveal that responsibility.
- [ ] Volatile work state is separate from durable knowledge.
- [ ] Each fact has one canonical owner.

## Evidence

- [ ] Paths, symbols, commands, and behavior match the repository.
- [ ] Intended design has a canonical source.
- [ ] Legacy examples have clear labels.
- [ ] Uncertainty and conflicts are visible.
- [ ] Commit, branch, review, tool, and release policies have repository evidence or user instruction.

## Structure

- [ ] The map or relationship appears before component descriptions.
- [ ] Rules appear before rationale.
- [ ] Exceptions appear next to the rules that they modify.
- [ ] Tables compare repeated fields only.
- [ ] Diagrams encode meaningful relationships.
- [ ] Directory maps are shallow and interpreted.

## Navigation

- [ ] Links name exact canonical paths.
- [ ] A local task does not require the full documentation tree.
- [ ] Deeper details live in linked documents.
- [ ] No section duplicates a linked source.

## Language

- [ ] Headings are short and descriptive.
- [ ] Each instruction starts with a verb.
- [ ] Each sentence contains one action or fact.
- [ ] List items with several actions or conditions are split.
- [ ] Conditions appear before instructions.
- [ ] Active voice identifies the actor.
- [ ] One term names each concept.
- [ ] Code, identifiers, commands, paths, keys, and quoted errors are unchanged.
- [ ] Instructions contain 20 words or fewer.
- [ ] Descriptions contain 25 words or fewer.

## Delete

- [ ] Generic introductions.
- [ ] Framework tutorials.
- [ ] Generic software advice.
- [ ] Motivational or rhetorical prose.
- [ ] Repeated summaries.
- [ ] Historical detail that does not change a decision.
- [ ] Filler and hedges such as `it is important`, `generally`, or `as needed`.
- [ ] Unmeasured adjectives such as `robust`, `powerful`, or `seamless`.

## Final gate

- [ ] A fresh agent can locate the relevant source.
- [ ] The agent can see allowed and forbidden behavior.
- [ ] The agent can identify the verification command.
- [ ] Every section supports action or navigation.
- [ ] The document stays within its default size limit, or the extra text prevents a concrete error.
